## 2. Chi tiết Fix 1: JAL/JALR Bug (Solution 1)

### File: `src/core/riscv_datapath.sv` — dòng 326-328

### Root cause
`branch_taken_o` được tính là:
```systemverilog
// TRƯỚC (SAI):
assign branch_taken_o = id_ex_valid
    && (id_ex_out.ctrl.br_req.is_branch || id_ex_out.ctrl.br_req.is_jump)
    && branch_taken_internal;
```
`branch_taken_internal` đến từ `branch_cmp.sv`, chỉ tính điều kiện BEQ/BNE/BLT/... Với lệnh JAL/JALR (`is_jump=1`), `branch_cmp` trả về kết quả bất kỳ (thường = 0 vì nó so sánh RS1 == RS2 theo kiểu BR_BEQ). Kết quả: `branch_taken_o = 0` → Control không tạo flush/PC-redirect → CPU tiếp tục chạy tuần tự qua lệnh JAL/JALR (fall-through).

### Fix áp dụng
```systemverilog
// SAU (ĐÚNG — Solution 1 từ log trước):
assign branch_taken_o = id_ex_valid
    && (id_ex_out.ctrl.br_req.is_jump                         // JAL/JALR: luôn nhảy
        || (id_ex_out.ctrl.br_req.is_branch && branch_taken_internal)); // BEQ/BNE/...: có điều kiện
```

**Tại sao đúng:**
- `is_jump=1` (JAL/JALR): không cần kiểm tra `branch_taken_internal` → luôn báo nhảy thành công
- `is_branch=1` (BEQ/BNE/...): vẫn kiểm tra `branch_taken_internal` như cũ → không thay đổi behavior

**Tác động:**
- Tất cả lệnh JAL/JALR trong `program_io.hex` (gọi hàm `lcd_send_cmd`, `lcd_send_data`, `uart_send_byte`) nay hoạt động đúng
- Các vòng lặp chính (`jal x0, main_loop`) thoát và nhảy đúng

## 3. Chi tiết Fix 2: DMEM Word Address (dmem.sv)

### File: `src/memory/dmem.sv` — dòng 37-42 và bounds checks

### Vấn đề tìm thấy
`word_addr` tính theo bit-slice:
```systemverilog
// TRƯỚC:
logic [ADDR_W-1:0] word_addr;
assign word_addr = req_addr_i[ADDR_W+1 : 2];   // chỉ lấy 10 bit thấp
```
Với DMEM_SIZE=4KB, ADDR_W=10: lấy `req_addr_i[11:2]`.

**Bug tiềm ẩn:** Địa chỉ `0x2000_1000` có `bits[11:2] = 10'h000` (do bit 12 set, không phải bit 11). Word_addr=0, bounds check `0 < 1024` → PASS → ghi nhầm vào word 0. Về lý thuyết không xảy ra với phần mềm hiện tại (DMEM chỉ dùng 0x2000_0000–0x2000_0FFC) nhưng là potential aliasing bug.

### Fix áp dụng (đồng nhất với imem.sv)
```systemverilog
// SAU:
logic [31:0] word_addr_full;
assign word_addr_full = req_addr_i >> 2;       // full 32-bit shift: an toàn với mọi địa chỉ
logic [ADDR_W-1:0] word_addr;
assign word_addr = word_addr_full[ADDR_W-1:0]; // truncate chỉ dùng để index mảng

// Bounds check dùng word_addr_full (không bị aliasing):
if (word_addr_full < WORD_COUNT) ...
```
Đây là cùng pattern với `imem.sv` — nhất quán trong codebase.

**Kết quả:** Hex file hiện tại đã đúng, không cần thay đổi.

### Disassembly highlights (đã verify)
| Label | Offset | Lệnh |
|-------|--------|------|
| `_start` | 0x000 | `lui sp, 0x20001; addi sp, sp, -4` → sp=0x20000FFC |
| `main_loop` | 0x00C | `lw t1, 0(t0)` → đọc GPIO |
| `mode_00_lcd` | 0x040 | `li a0, 0x38; jal ra, lcd_cmd_wait` |
| `mode_01_led` | 0x0E0 | `mul a0, s1, s1; slli a0, a0, 10` |
| `mode_02_uart` | 0x10C | `divu x29, a0, x28 (100)` → hàng trăm |
| `lcd_cmd_wait` | 0x190 | poll LCD_STATUS, sw a0, 0x28(t0) |
| `lcd_data_wait` | 0x1AC | poll LCD_STATUS, sw a0, 0x2C(t0) |
| `uart_send_byte` | 0x1C8 | poll UART_STATUS[0], sw a0, 0x08(t0) |
| `trap_handler` | 0x1F0 | save context, csrr t3, mcause, mret |

**Lưu ý về mtvec:** `program.s` hiện không setup `mtvec` → trap mặc định đến địa chỉ 0 (re-execute _start). Cho thesis demo (LCD/LED/UART TX), đây không phải vấn đề vì không có trap hardware. UART RX interrupt là optional feature.

## 6. Testbench: verify/tb_soc_io.sv

### Cấu trúc
```
tb_soc_io
├── DUT: soc_top_io (imem=program_io.hex, 50MHz, 115200 baud)
├── Clock: 50MHz (20ns)
├── uart_rx_i: tied HIGH (idle, no incoming data)
├── Monitors (passive):
│   ├── LCD strobe (posedge lcd_en_o → print CMD/DATA)
│   ├── LED change (led_o transition)
│   └── Register writeback spy (WB stage)
└── Stimulus + PASS/FAIL checking (13 checks)
```

### Tests
| Test | Mode | Input | Expected | Checks |
|------|------|-------|----------|--------|
| 1 | Mode 00 | sw=00 | LCD cmds+data | lcd_on=1, lcd_rw=0 |
| 2a | Mode 01 | N=5 | LED=25 | led_o === 25 |
| 2b | Mode 01 | N=15 | LED=225 | led_o === 225 |
| 2c | Mode 01 | N=0 | LED=0 | led_o === 0 |
| 2d | Mode 01 | N=10 | LED=100 | led_o === 100 |
| 3a | Mode 02 | N=42 | "42\r\n" | 4 UART bytes: 0x34,0x32,0x0D,0x0A |
| 3b | Mode 02 | N=100 | "100\r\n" | 5 UART bytes: 0x31,0x30,0x30,0x0D,0x0A |

**Tổng: 2 + 4 + 7 = 13 PASS/FAIL checks**

### UART capture task
- Phát hiện start bit bằng cách đếm clock cycles (không dùng `@(negedge)` để tránh deadlock khi UART idle)
- Timeout = 200K cycles (4ms)
- Sample tại bit-center: delay 1.5 × BIT_PERIOD sau start bit, rồi mỗi BIT_PERIOD lấy 1 bit

### Chạy simulation
```bash
cd sim
vsim -do run_soc_io.do
```
File `sim/run_soc_io.do` đã tồn tại và compile đúng thứ tự.
