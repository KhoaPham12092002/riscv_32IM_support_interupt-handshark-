## Phân tích nguyên nhân có thể

### Khả năng A — CPU bị treo trước khi vào `mode_00`
CPU chạy nhưng stuck trong vòng lặp trước khi tới `hex_loop`. Có thể bị kẹt tại:
- Lệnh `lw` đọc KEY (0x40002000): nếu IO response timing sai → LSU stuck ở WAIT_RSP mãi mãi
- Lệnh `lw` đọc SW (0x40000000): tương tự
- Lệnh `sw` ghi LED (0x40000000): IO write, có thể không nhận ACK đúng cách

### Khả năng B — `_init` chưa chạy xong, `x30` = 0 (uninitialized)
Nếu `li x30, 0x20000000` chưa kịp writeback khi `hex_loop` dùng x30:
- `add x7, x30, x6` → x7 = 0 + digit → load từ addr=0x00000000 (IMEM, không phải DMEM)
- `lbu` từ IMEM → LSU route sang DMEM không tìm thấy → `rsp_valid` không bao giờ về → CPU treo

### Khả năng C — `cs_hex` không được assert
`periph_addr_t'(io_addr & 20'hFF000)` có thể không match `ADDR_HEX = 20'h01000`:
- Nếu `dmem_addr[19:0]` tại thời điểm decode không phải `0x01000` → `cs_hex = 0`
- HEX write bị bỏ qua silently

### Khả năng D — IO response cho LOAD bị mất
`io_rsp_valid <= io_req_valid` (1-cycle delay). Nếu LSU chuyển sang WAIT_RSP đúng lúc `is_io_access` bị deassert → `dmem_rsp_valid = real_dmem_rsp_valid` (DMEM) thay vì `io_rsp_valid` → LSU chờ DMEM response mà không có → stuck mãi.

Cụ thể: khi LSU vào WAIT_RSP, `dmem_req_valid_o = 0`. Nếu `dmem_addr_o` không còn giữ đúng địa chỉ IO → `is_io_access` có thể flip về 0.

### Khả năng E — Hex file không load đúng
`$readmemh` không tìm thấy file (path sai relative to sim directory) → IMEM toàn NOP → CPU fetch NOP mãi.

## Hướng debug trong session mới

### Bước 1 — Xác nhận CPU đang chạy
Trong waveform, tìm PC (hoặc `if_req_addr`):
- Nếu PC tăng lên → CPU đang fetch
- Nếu PC stuck tại 1 địa chỉ cố định → CPU bị treo, note lại địa chỉ đó
- Nếu PC = 0x00000000 và không thay đổi → IMEM không load hex file (Khả năng E)

**Tìm signal:** `sim:/tb_soc_io/u_soc/u_datapath/` → tìm `if_req_addr` hoặc `pc` trong IF stage.

### Bước 2 — Check DMEM _init (500 cycle đầu sau rst)
Zoom vào khoảng `t=400ns` đến `t=10400ns` (20 đến 520 cycles):
- `real_dmem_req_valid` có lên 1 không?
- `dmem_we = 1` và `dmem_addr = 0x20000000..0x20000009` không?
- Nếu không có → `_init` fail → Khả năng A hoặc E

### Bước 3 — Check IO access
Tìm bất kỳ cycle nào có `io_req_valid = 1`:
- `io_req_valid` có bao giờ lên 1 không?
- Nếu không → CPU bị treo trước khi reach instruction nào dùng IO

Nếu `io_req_valid = 1`:
- `cs_hex` có = 1 khi addr = 0x40001xxx không?
- `io_we = 1` khi write HEX không?

### Bước 4 — Check IO response timing (Khả năng D - nghi nhất)
Zoom vào 1 lần `io_req_valid = 1` cho LW (load):
```
Cycle N:   io_req_valid=1, dmem_req_valid=1 (LSU SEND_REQ)
Cycle N+1: io_req_valid=0, dmem_req_valid=0 (LSU WAIT_RSP)
           io_rsp_valid=1 (từ cycle N)
           is_io_access = ???  ← CHECK THIS
           dmem_rsp_valid = ???
```
Nếu `is_io_access = 0` ở cycle N+1 → `dmem_rsp_valid = real_dmem_rsp_valid = 0` → LSU stuck forever.

**Nguyên nhân:** `is_io_access = (dmem_addr[31:28] == 4'h4)`. Nhưng `dmem_addr = dmem_addr_o` từ LSU luôn driven từ `addr_q` → vẫn = IO address khi ở WAIT_RSP. Nếu `is_io_access` vẫn = 1 thì không phải vấn đề này.

### Bước 5 — Nếu CPU bị treo, xác định tại lệnh nào
Nhìn PC khi stuck, tra địa chỉ trong disassembly:
```bash
riscv32-unknown-elf-objdump -d programv2.elf
```
Địa chỉ stuck → biết CPU đang ở lệnh gì → suy ra tại sao treo.

## Fix nhanh có thể thử

### Fix 1 — Tăng WAIT_CYCLES trong testbench (nếu timing _init quá chậm)
```sv
// verify/tb_soc_io.sv
localparam int WAIT_CYCLES = 60_000;  // tăng từ 30000
```
Và tăng thời gian chờ _init:
```sv
repeat (2000) @(posedge clk);  // tăng từ 500
```

### Fix 2 — Check IO response cho LOAD (Khả năng D)
Trong `soc_top_io.sv`, thêm signal `io_rsp_valid_safe` để đảm bảo LSU nhận đúng:
```sv
// Giữ is_io_access trong 1 cycle để io_rsp_valid có thời gian được nhận
logic is_io_access_q;
always_ff @(posedge clk_i) is_io_access_q <= is_io_access;

assign dmem_rsp_valid = (is_io_access || is_io_access_q) ? io_rsp_valid : real_dmem_rsp_valid;
```

### Fix 3 — Thêm debug wave signals
Trong `run_soc_io.do`, thêm PC và LSU state để dễ trace:
```tcl
add wave -noupdate -label "PC (IF)"      -radix hex sim:/tb_soc_io/u_soc/u_datapath/if_req_addr
add wave -noupdate -label "LSU state"    sim:/tb_soc_io/u_soc/u_datapath/u_lsu/state
add wave -noupdate -label "io_rsp_valid" sim:/tb_soc_io/u_soc/io_rsp_valid
add wave -noupdate -label "is_io_access" sim:/tb_soc_io/u_soc/is_io_access
```
